网页预览修复

2026-11-14 · 本机工程修复 · 界面验收仍由用户手动完成

现象

点击「预览此版本」能看到网页首屏，但点击网页里的菜单链接，或切换「手机版／桌面版」之后，内容显示不出来。

原因

  • 预览 iframe 原先使用 srcDoc，文档地址是 about:srcdoc，没有自己的 URL。网页里的 href="#menu" 被浏览器解析成父页面地址，在沙箱中拒绝加载，菜单锚点因此点了没有反应。
  • 预览图片使用父页面创建的 blob: 地址；沙箱 iframe 是独立源，浏览器以「Not allowed to load local resource」拒绝，图片也显示不出来。

修复

  • 预览文档改为自包含的 data:text/html 地址，菜单、联系方式等锚点可以正常跳转滚动。
  • 图片缩放后内嵌为 data URL；超出浏览器 data URL 大小预算时按体积降级为占位并提示，不让整个预览变空白。
  • 新增「在新窗口打开完整预览」，可查看原图与完整尺寸；PDF 仍只在预览区下方下载。
  • 切换桌面／手机时重建 iframe，从网页顶部重新显示，避免停在重排后的空白位置。
  • 继续保留无同源权限的 sandbox 与 CSP：禁用脚本、表单、网络连接和任意外部资源。

工程校验

  • 新增 4 项 Playwright 回归：资源地址改写安全、大图降级、新窗口完整预览、沙箱内锚点与尺寸切换。
  • 用真实 Chome 版本（27 道菜）验证：点击 Menu 后地址变为 #menu、滚动 1243px；切换手机后内容仍在且回到顶部；浏览器控制台无错误。
  • 前端类型检查与构建通过；后端 166 项真实 PostgreSQL 回归全部通过，无跳过。

手动验收

  1. 刷新 https://localhost:5173，选择餐厅 → 网页生成。
  2. 点击「预览此版本」。
  3. 点击预览网页里的 Menu，应滚动到菜单区。
  4. 切换「手机 · 390px」／「桌面」，应重新从网页顶部完整显示。
  5. 点「在新窗口打开完整预览」查看原图与完整尺寸。

边界

这只是本机隔离预览，不等于公网发布。正式域名、云端托管与 HTTPS 尚未配置；顾客订位、订阅与访问统计仍未实现。
