订位：数据库、接口与网页组件

2026-11-14 · 数据库/接口/生成页组件/站点订位页 · 商家管理页面、真实邮件与公网未完成

订位按“提交申请 → 商家确认或拒绝”实现。提交不等于有位，没有容量、桌位或拼桌分配，也不承诺实时可订。本轮交付数据库迁移、接口、生成页固定组件与站点订位表单。

01 / 新增与扩展的数据

  • reservations：顾客姓名、邮箱或电话、人数、餐厅本地日期/时间、时区快照、换算后的UTC时刻、状态、revision、幂等键与公开编号。原始申请字段由触发器保护，不可改写。
  • reservation_events：只追加的变更历史，状态迁移与revision一一对应，同店同request_id唯一，用于幂等与审计。
  • reservation_access_tokens：顾客管理令牌只存HMAC摘要，一预订一活跃令牌，有效期120天，可由顾客查看和取消。
  • email_outbox扩展：允许游客预订通知（restaurant_id + reservation_id），模板增加received/confirmed/declined/cancelled，payload只允许固定摘要键。
  • audit_logs扩展：新增订位设置、商家决策和取消动作，实体类型增加reservation。
  • 餐厅已有reservation_enabled、reservation_notice、privacy_notice_version，008补齐应用角色更新权限。

迁移文件：008_reservations.sql；未修改001–007已执行迁移。

02 / 商家接口

接口作用保护
GET /api/v1/restaurants/:id/reservations/settings读取是否开启、说明、隐私版本、时区与营业段登录+归属
PATCH .../reservations/settings开启或停订；设置说明与隐私说明版本登录+CSRF+revision
GET .../reservations按状态、本地日期筛选，游标分页登录+归属
GET .../reservations/:reservationId详情与最近事件登录+归属
POST .../:reservationId/decision确认或拒绝；拒绝必须给顾客可见原因登录+CSRF+revision+幂等键
POST .../:reservationId/cancel商家取消pending或confirmed登录+CSRF+revision+幂等键

开启订位会递增餐厅revision，可能使命中中的网页生成确认失效，需要重新核对；这是既有“资料变更撤销确认”的一致行为。

03 / 顾客接口

接口作用保护
POST /api/v1/public/restaurants/:slug/reservations游客提交订位申请，返回一次管理令牌营业/隐私/限流/幂等键/站点Origin
GET /api/v1/public/reservations/:token凭令牌查看状态与餐厅信息高熵令牌，不可枚举
POST /api/v1/public/reservations/:token/cancel顾客取消pending或confirmed令牌+revision，仅POST
  • 令牌只在创建响应返回一次，数据库只存摘要；不能凭邮箱、公开编号或自增ID查询。
  • 公开响应不回显完整邮箱与内部备注；商家响应含联系方式和内部备注，便于处理。
  • 不提供GET取消，避免邮件扫描器或预取改变状态。提交与取消均校验幂等/revision，重复提交不会生成第二笔。
  • 公开接口由站点同源调用；生产环境只接受站点origin，本地开发额外允许管理origin便于手测，未开放任意跨站来源。

生成网页与站点订位页

  • 生成器新增固定组件 <restaurant-reservation>：开启订位时渲染说明和“提交订位申请”入口；模型没写也会自动补；未开启显示联系提示。
  • 入口指向平台固定页面 /s/<slug>/reserve，收集姓名、邮箱或电话、日期、时间、人数、备注，并要求确认隐私说明；生成网页本身仍不运行表单或脚本。
  • 提交同源到站点服务，复用与公开API相同的营业、时区、幂等和事务校验；成功页显示编号、pending状态和 /r/<token> 管理链接。
  • 管理页可查看状态并取消；取消只接受POST与revision，GET不会改变状态。站点页仅放宽 form-action 'self'，无脚本，生成网页的沙箱和禁表单不变。

04 / 业务校验与状态机

  • 只接受餐厅accepts_requests=true的营业段，含跨午夜；不存在的日期/时间、超出90天窗口、提前不足15分钟均拒绝。
  • 以餐厅时区把本地日期时间换算为唯一UTC时刻：夏令时跳过的本地时间直接拒绝；回拨造成两个可能时刻时要求明确偏移，不静默猜测。
  • 人数固定1–20（首版上限，可在后续迁移调整）；邮箱或电话至少一个；顾客备注最多1000字符。
  • 状态只能pending → confirmed / declined / cancelled，confirmed → cancelled；终态不可变；每次变更revision+1并由数据库触发器强制。
  • 商家决策与取消写事件、审计并在同一事务排队通知；邮件失败不影响订位状态，SMTP未配置时不发送、不伪造成功。
