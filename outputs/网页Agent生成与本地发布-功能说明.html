现在可以做什么

功能实际行为
需求引导结合已保存的餐厅资料讨论风格、布局、语言及缺项；对话与revision持久保存。也可跳过聊天，直接填写生成需求。
选择资料与素材核对真实资料，选择本店已上传素材并确认允许公开。最多8份；菜单原文件、Logo各最多1份。
真实网页生成调用官方model deepseek-flash。生成布局和CSS，由后端插入固定真实资料；拒绝脚本、表单、外部资源和虚构菜单文字。不使用假模板伪装模型成功。
持久任务与版本排队、处理中、成功或失败可追踪；输入及网页版本冻结，HTML正文和素材摘要持久保存。未知结果重试保留原幂等键，不自动再次计费。
桌面／手机预览生成页面在无脚本、无同源权限的受限iframe中展示；选择图片使用授权Blob。PDF只提供下载，不内嵌执行。
本地发布／回滚单独确认版本后，发布到独立只读服务。切换或回滚网站指针，不清空账户和业务数据。发布前核验素材真实文件，失败保留旧指针。

你怎么手动测试

  1. 打开 https://localhost:5173，使用原测试账号，选择餐厅，进入网页生成。首次访问本地自签名HTTPS可能需要浏览器确认。
  2. 核对已保存餐厅资料；如要修改，先去餐厅资料页保存。菜单和照片在“菜单与图片”上传。
  3. 向Agent描述风格，或直接填写官网需求摘要。例如：“白底、大留白、细字体、深绿点缀；先品牌介绍，再展示图片、菜单和联系方式。”
  4. 选择素材并勾选真实性及公开使用确认，点击生成。等待真实任务完成；结果未知时点“核查并重试”，不要反复开启新任务。
  5. 点击“预览此版本”，切换桌面和390px手机。检查文字、图片、菜单原文件下载、联系方式和营业时间。
  6. 填本地路径，例如 my-restaurant，确认公开展示后发布。页面会提供 http://localhost:4174/s/my-restaurant。该路径第一次发布后固定，不是域名注册。
  7. 修改需求再生成一版，检查旧站不自动变化。确认发布新版，然后选择旧版确认回滚，检查网址不变而内容切回。

菜单识别目前的边界

“识别菜单（稍后开放）”入口保留但禁用，没有OCR请求。所选菜单图片或PDF只作为原文件查看／下载，不提取菜名、菜价、过敏原，也不自动得到可编辑的结构化菜单。没有菜单时网页提示联系餐厅获取菜单，不凭空编造。

本地启动与技术入口

三个进程：

npm --prefix backend run dev
npm --prefix frontend run dev
npm --prefix backend run sites:dev

管理平台HTTPS5173 → API4000；公开页面只读服务HTTP4174。密钥仅在后端私有配置中加载，不进入前端、HTML、日志或Git。菜单／照片授权清单跟随版本冻结，被网页引用的素材不能直接删除。

API基址：/api/v1/restaurants/:restaurantId/website。GET状态；POST /messages、/generations、/publication；GET /versions/:versionId/preview、/jobs/:jobId。写请求必须带会话、CSRF及幂等键；各自revision防并发覆盖。
