网页生成从一次性输出改为工具式 ReAct

读取真实能力和确认资料 → Agent 自己制定 Plan／TODO → 写草稿 → 调用真实 HTML／CSS 检查 → 收到错误修复 → 再检查 → 完成后保存预览版本。发布仍由商家另行确认。

这次解决什么

  • 正常语义 HTML、表格、图文布局、details、内联样式及现代 CSS 函数不再因人工小白名单被拒绝；未知纯样式函数不会仅因为名称未登记而失败。
  • 语法检查返回实际文件、行、列、错误码与说明，Agent 按真实反馈继续修改，而不是第一次不合格就直接结束。
  • 模型自己制定和维护计划，执行器只验证动作权限和完成条件，不伪造 Agent 的计划或“检查通过”。
  • 菜单／营业／联系方式组件展开后的最终 HTML 也检查结构；不会让浏览器偷偷修补非法嵌套然后声称语法正确。
  • 管理页显示计划状态、稿次、修复轮次、模型调用数、累计已知用量和具体错误。生成按钮旁显示当前被禁用的真实原因。

怎样连接真实后端

本次不是把模型返回的代码直接连数据库。Agent 运行在已鉴权的后端任务中，读取该餐厅的冻结快照，写入虚拟草稿；计划／错误／轨迹保存到真实 PostgreSQL。完成后由服务器保存不可变网页版本，选中素材继续使用已有授权与引用保护。

给模型的说明已作为实际文件加载到工具上下文：website-agent-capabilities.json。它列出真实已有接口、可用组件、执行权限和未完成业务，而不是给模型整个后台的访问凭据。

能力实际执行结果

不是完全撤掉安全

已取消过窄的设计名单，但保留静态网站能力边界：不执行模型脚本／事件，不允许任意外网资源、表单和嵌入页，不给模型顾客数据或商家特权；公开页面继续独立域／沙箱／CSP。确认菜单的菜名和原价由后端组件填入，模型只能排版。

普通文案可以自由表达，语法校验不能证明其内容真实，商家仍须预览审核。菜单核对备注和警告既不对顾客展示，也不发送给布局模型。素材只按准确的资源属性替换，不因正文出现占位符前缀误杀整个网页。

循环与费用限制

  • 最多4稿：初稿＋3轮修复；最多12次模型调用、24个工具动作、8分钟。
  • 累计60,000 tokens预算；每次外发前按消息／工具定义UTF-8字节保守预留输入，剩余额度才分配输出。不足预算停止，不将缺失用量伪装为0。
  • 仅保留当前草稿、实际状态和最近完整原生工具结果，避免旧稿无限累积；不能丢掉工具反馈让模型每轮重新开始。
  • 语法或工具参数不合格可在同一任务里修复；余额不足、网络超时、授权失效、达到预算直接停止，不盲重试计费请求。
  • 每账号滚动24小时30个任务是任务额度，不是模型调用额度。一次任务可能多次调用模型并产生更多费用。
  • 进程中断后保留草稿／诊断，已过期运行任务失败，不自动续跑付款调用。历史失败任务不会被本次升级自动重新生成。

你如何测试

  1. 用自己的浏览器打开 https://localhost:5173，原账号登录，选择餐厅 → 网页生成。
  2. 核对菜单已人工确认；填写官网需求摘要并勾选当前资料和素材公开确认。按钮旁若仍有阻止原因，按对应提示处理。
  3. 点击一次生成，观察模型计划、写稿、校验与可能的修复进度。没有错误时直接完成；有错误时会显示具体位置与修复轮次。
  4. 完成后检查预览、菜名、价格、布局与图片，再显式确认本地发布。不会因模型完成就自动发布。
  5. 旧失败记录仍保留，不代表新任务也失败；查看本次任务的时间、稿次和状态。
